## 1. 当前状态

- 本地候选版 **beta0.5 · 荔枝庭院**，Windows x64。起点 `457353f`；PR #1 已合并到 main（`1644f09`），其测试及各平台构建通过；按用户要求恢复原有星露谷式界面，修正分支为 `fix/restore-pixel-campus`，未打版本标签或发布 Release。
- 本轮按用户 8 条反馈完成：整页滚动、卡号默认隐藏、生成校园背景、移除重复仿标题栏、本地伙伴/农田完整循环、校内后端业务分层、学习工具与备份、无 CMD 启动和设置内退出。
- 默认桌面构建排除实验 VPN 协议和未核实的旧游戏原型素材；保留官方 WebVPN 入口，恢复带 OFL 声明的 Fusion Pixel 字体与项目自绘花草。F06/F07/F08/F11 并未假装修好，仍约束实验模块的未来发行。
- 校园网已有双协议认证、接入点发现、注销和诊断；真实教学区/宿舍验证仍待进行。第三方学校业务以可搜索的官方入口呈现，余额、成绩、课表自动读取未接入。
- 数据现在写入用户目录 `.szunet/workspace-v1.json`，跨进程/端口恢复、版本冲突保护、导入导出。旧浏览器 localStorage 不会自动跨端口迁移。
- 产品定位：校园生活助手；校内服务器业务方案在第 9 节，尚未部署。本机存档和伙伴农田无需远程后端。

## 2. 分类方法

| 维度 | 标记 | 含义 |
| --- | --- | --- |
| 重要程度 | P0 | 发布阻断：凭据/安全、未认证报成功、代码许可来源；相关功能对外发布前解决 |
| 重要程度 | P1 | 当前核心必修：正常操作、真实状态、内容可见、数据可靠；功能扩展前完成 |
| 重要程度 | P2 | 近期体验/功能：不阻断基础使用，但提高效率与价值 |
| 重要程度 | P3 | 长期或低频功能，先记录范围 |
| 难度 | S 容易 | 单点或少量文件、依赖明确、可本地回归 |
| 难度 | M 中等 | 多处联动、页面结构或数据层改造，需要跨页验证 |
| 难度 | L 较难 | 协议/平台/认证链路或外部证据依赖，需要专项验证 |

按 **P0/P1 × S → P0/P1 × M/L → P2 × S/M → 其他** 执行。难度不是工期承诺。
“已完成”须有验收证据；“部分完成”不关闭剩余范围；本轮未做真实账号认证或校外 VPN 测试。

## 9. 校内服务器能承担哪些业务

可以将公共业务放在校内服务器，桌面本机服务继续负责账号凭据和网络认证。校内托管本身不会自动获得教务等系统的 API 权限，也不意味着校外用户可以直接访问该服务器。

| 业务 | 是否需要后端 | 优先/难度 | 建议方案与边界 |
| --- | --- | --- | --- |
| 官方服务目录、常用入口、应用版本清单 | 推荐 | P2 / S | 可先用静态 JSON + HTTPS；每项有来源、校区、更新时间，离线回退本地目录 |
| 学校公告、讲座、办事通知聚合 | 需要 | P2 / M | 定时抓取允许访问的公开来源，去重、缓存、搜索；保留原文链接与抓取时间，不复制整篇文章冒充原创 |
| 官方校历/考试周/公共地点资料 | 推荐 | P2 / S–M | 后台统一录入核实数据，客户端缓存；个人教学周仍能本地手动设定 |
| 公告关键词订阅、提醒收件箱 | 需要 | P2 / M | 用户选择订阅范围；首期应用内提醒，邮件/外部推送需单独选择，不默认发消息 |
| 跨设备庭院/待办同步 | 需要 | P3 / L | 自愿注册或授权登录，存档版本、冲突副本、删除/导出、备份与速率限制；不上传校园密码 |
| 反馈与崩溃上报 | 可选 | P2 / M | 用户主动提交，脱敏后预览；日志不含账号密码和会话 token，不默认采集 |
| 排行、访客、多人庭院、交易 | 需要 | P3 / L | 服务器校验经济规则与身份、反滥用和内容管理；初版不做 |
| 课表/成绩/余额/借阅 | 视接入方式 | P2 / L | 优先官方接口和明确授权；个人会话本地持有或可撤销短期票据，不替用户长期保管统一认证密码 |
| 校园网登录/注销、网络诊断 | 不应迁移 | P1 / M | 与使用者网卡/出口相关，留在本机执行；后端不能代表用户的网口完成认证 |
| 单机伙伴、种地、专注、绩点、备份 | 不需要 | 已完成 | 本机离线工作，避免服务器故障拖垮基础体验 |

**首期架构**：HTTPS 反向代理 → 一个只读公共 API 服务 → SQLite/轻量数据库与定时采集。个人账户出现后再引入会话和按用户隔离的数据表，避免一开始做过大的后台。可使用 Go 与现有代码统一；数据库定期备份并演练恢复。

**首期接口建议**：`GET /v1/catalog`、`GET /v1/notices?source=&cursor=`、`GET /v1/calendar?term=`、`GET /v1/releases/latest`、`GET /healthz`。响应含 schemaVersion/source/updatedAt，ETag 与过期缓存；数据源采用允许列表，不提供任意 URL 转发。创建订阅和同步接口等到认证方案确定后单独接入。

## 12. 从首次使用到公开发布的用户体验复核（2026-09-18）

**结论：适合定向、小范围 Beta 试用；暂不建议按“已完善的校园助手”面向全校宣传。** 已有可运行的初版，剩余工作以首次体验、运行/退出、真实校园验证和发布渠道为主，不需要先完成校内后端或继续扩充玩法。本节是发布前的剩余清单，前文“已完成”只表示对应实现和已列明的本地验证，不代表整个产品已达到公开首发标准。

### 12.1 本轮证据与边界

- 用实际 beta0.5 exe 和全新临时存档检查首页、学习、设置；实际新增待办、启动 5 分钟专注并跨页查看。首页能显示“继续当前专注”，设置提供本地备份和完整退出，账号没有预填。
- 在 1366×768 首屏，顶部招牌、导航及欢迎区到约 450px；待办和常用服务位于首屏下缘。可滚动但首次到达常用任务的效率仍有提升空间。
- 同一临时存档启动两个进程，两个窗口先读取同一状态；第一个新增待办后，第二个点击摸摸头，显示“另一个窗口更新了存档，请重新加载后继续”。冲突保护有效，但用户需要自己刷新。关闭第二个页面后两个进程仍存在；随后通过第一个窗口的设置→退出应用确认其对应进程结束，页面显示已退出。另一个残留的测试进程单独清理。
- 当前界面未提供应用内反馈入口、打开下载页/更新说明入口或首次使用引导。专注页面有倒计时与完成领取；源码未实现跨页到时提醒或后台系统提醒。本轮没有等待完整 5 分钟，不将提醒缺失写成到时实测结果。
- 宠物默认为黄色猫咪且叫“荔宝”，对话框同名角色是粉色荔枝形象，角色身份尚未明确区分。背景细节、粗像素花草和角色的像素尺度不统一。
- 实时核对 GitHub：PR #2 仍 OPEN，代码提交 e55048c 的测试及各平台构建均成功，release 步骤跳过；公开最新预发布仍是 beta0.4（2026-09-17），不能告诉新用户已能从 Release 下载 beta0.5。
- 本轮没有真实校园账号、教学区/宿舍现场登录，没有第二台干净 Windows 设备，也没有验证系统信誉提示；这些是验收缺口，不直接断言对应功能失败。

### 12.3 有限范围的发布建议

1. 先完成 B02/B04/B05/B06 的小规模收尾；B07 做一次统一，不重新设计整套产品。B01 需要实际校园环境验收，代码检查不能替代。
2. 找 10–20 位同学定向试用，覆盖教学区、宿舍和校外。请他们独立完成“打开应用、找官方服务、使用庭院/待办、退出再打开”；记录卡住的位置和是否愿意第二天继续用。人数是建议，不是已完成测试。
3. 公开 Beta 门槛：核心登录按宣传范围完成实测；重复启动/退出和存档不误导；新版下载一致；至少一个反馈入口；现有老用户有升级说明。根据实测修复问题后再宣传。
4. 初版不必等待云同步、排行榜、多宠物、多人庭院、自动课表/余额、完整校内后端。现阶段这些不是阻止初版发布的原因。
5. 宣传定位采用“像素风校园小工具 + 本地学习/庭院陪伴”，明确学校服务主要是官方入口；可作为 Beta 发布，不写成已接入所有学校业务的正式 1.0。
