## 2. 分类方法

| 维度 | 标记 | 含义 |
| --- | --- | --- |
| 重要程度 | P0 | 发布阻断：凭据/安全、未认证报成功、代码许可来源；相关功能对外发布前解决 |
| 重要程度 | P1 | 当前核心必修：正常操作、真实状态、内容可见、数据可靠；功能扩展前完成 |
| 重要程度 | P2 | 近期体验/功能：不阻断基础使用，但提高效率与价值 |
| 重要程度 | P3 | 长期或低频功能，先记录范围 |
| 难度 | S 容易 | 单点或少量文件、依赖明确、可本地回归 |
| 难度 | M 中等 | 多处联动、页面结构或数据层改造，需要跨页验证 |
| 难度 | L 较难 | 协议/平台/认证链路或外部证据依赖，需要专项验证 |

按 **P0/P1 × S → P0/P1 × M/L → P2 × S/M → 其他** 执行。难度不是工期承诺。
“已完成”须有验收证据；“部分完成”不关闭剩余范围；真实验证进展以第 14 节为准：已在学校官方 WebVPN 完成登录并查看场地时段；不等于校园网双协议认证已现场验收。

## 6. 开发与发布约定

- 页面壳源文件 `desktop/index.html`，行为/样式/规则位于 `desktop/assets/garden/`；`desktop/assets/index.html`、`desktop/internal/ui/assets/` 为生成副本，勿手改。HTML id 修改须检查 JS 引用；不手改 embed 副本。默认构建包含 index.html、图标、garden 目录，以及允许列表内的 Fusion 字体、CSS 和 OFL 声明；不复制整个旧 fonts/art 目录。

- 接入点编号不写死：手动 > 按网口缓存 > 可信跳转 > 猜测；探测不使用门户自身制造默认编号。深澜错误须读取 Error/ErrorMsg/SucMsg/Res。
- 普通用户默认不见 ac_id，相关错误才展开；不要给用户暴露源码维护要求。
- 测试必须用 SZUNET_CONFIG_DIR 隔离，不使用真实账号，只终止自己启动的 PID，不调整用户现有代理。
- 验证：node desktop/check-ui.mjs、go test ./...、go vet ./...、gofmt、python desktop/build-windows.py、python desktop/smoke_windows.py；界面另做实际浏览器检查。

- 代码/素材先核实来源及版本许可，不能把未核实实现宣传成独立实现；F11 未关闭前相关发布受阻。
- 不将假数字当真实数据。规划和状态只改本文，历史资料冻结，不再同步多套清单。
- 仓库公开，不迁入真实凭据、内网拓扑和未公开接口；原始调研保留本地作为证据。
- 标签触发发布 CI；版本号只有一个来源 `internal/version/VERSION`：两个 main.go 通过 `internal/version` 包读取（go:embed 编进二进制，不依赖 ldflags），页面顶栏与关于页从 `/api/status` 的 `app_version` 取值，构建与打包脚本读同一个文件。页面源码里不允许再写死版本号，`check-ui.mjs` 与 `smoke_windows.py` 各有回归守住这一点。README / 发布说明中的版本文字仍在发版时手工更新。历史阶段仅授权 PR；2026-09-19 用户已明确要求推送安装包，授权合并已通过检查的修复并发布 beta0.5.1。

### 8.1 伙伴

- 属性：饱食、精力、心情、亲密度、成长值/等级。摸摸 +2 成长、10 秒冷却；玩耍 +5 成长、消耗 10 精力、30 秒冷却；喂食 +30 饱食、+8 成长。
- 离线结算：饱食每小时 -2、心情 -1；醒着精力 -1，睡眠每小时 +30。单次衰减按最多 48 小时算，下限 15/20，伙伴不死亡；作物成熟后不枯萎。
- 每 50 成长升一级，上限 20。Lv.2 解锁蓝莓，Lv.3 解锁荔枝；改名、3 种永久装饰购买/收起/摆放。
- 普通食物 8 币一份；农田收成可直接喂食。食物紧缺有每日补给，不做付费等待。

## 9. 校内服务器能承担哪些业务

可以将公共业务放在校内服务器，桌面本机服务继续负责账号凭据和网络认证。校内托管本身不会自动获得教务等系统的 API 权限，也不意味着校外用户可以直接访问该服务器。

| 业务 | 是否需要后端 | 优先/难度 | 建议方案与边界 |
| --- | --- | --- | --- |
| 官方服务目录、常用入口、应用版本清单 | 推荐 | P2 / S | 可先用静态 JSON + HTTPS；每项有来源、校区、更新时间，离线回退本地目录 |
| 学校公告、讲座、办事通知聚合 | 需要 | P2 / M | 定时抓取允许访问的公开来源，去重、缓存、搜索；保留原文链接与抓取时间，不复制整篇文章冒充原创 |
| 官方校历/考试周/公共地点资料 | 推荐 | P2 / S–M | 后台统一录入核实数据，客户端缓存；个人教学周仍能本地手动设定 |
| 公告关键词订阅、提醒收件箱 | 需要 | P2 / M | 用户选择订阅范围；首期应用内提醒，邮件/外部推送需单独选择，不默认发消息 |
| 跨设备庭院/待办同步 | 需要 | P3 / L | 自愿注册或授权登录，存档版本、冲突副本、删除/导出、备份与速率限制；不上传校园密码 |
| 反馈与崩溃上报 | 可选 | P2 / M | 用户主动提交，脱敏后预览；日志不含账号密码和会话 token，不默认采集 |
| 排行、访客、多人庭院、交易 | 需要 | P3 / L | 服务器校验经济规则与身份、反滥用和内容管理；初版不做 |
| 课表/成绩/余额/借阅 | 视接入方式 | P2 / L | 优先官方接口和明确授权；个人会话本地持有或可撤销短期票据，不替用户长期保管统一认证密码 |
| 校园网登录/注销、网络诊断 | 不应迁移 | P1 / M | 与使用者网卡/出口相关，留在本机执行；后端不能代表用户的网口完成认证 |
| 单机伙伴、种地、专注、绩点、备份 | 不需要 | 已完成 | 本机离线工作，避免服务器故障拖垮基础体验 |

**首期架构**：HTTPS 反向代理 → 一个只读公共 API 服务 → SQLite/轻量数据库与定时采集。个人账户出现后再引入会话和按用户隔离的数据表，避免一开始做过大的后台。可使用 Go 与现有代码统一；数据库定期备份并演练恢复。

**首期接口建议**：`GET /v1/catalog`、`GET /v1/notices?source=&cursor=`、`GET /v1/calendar?term=`、`GET /v1/releases/latest`、`GET /healthz`。响应含 schemaVersion/source/updatedAt，ETag 与过期缓存；数据源采用允许列表，不提供任意 URL 转发。创建订阅和同步接口等到认证方案确定后单独接入。

**部署前仍需确定**：校内主机与域名、HTTPS 证书、允许的外网访问方式、服务运行用户/备份位置、公开数据源授权与抓取频率。当前没有这些部署信息，因此没有擅自创建远程服务，也没有假称后端已经上线。

## 13. 现有 Bug 修复与无老用户范围确认（2026-09-18）

用户明确：现在没有老版本用户。本轮不做迁移助手，移除应用内及发布说明里的旧版迁移负担；保留本机备份恢复。发布复核任务编号改为 Q01–Q12，避免与早期业务清单 B11/B12 重名。

- **重复启动**：使用按配置目录隔离的操作系统文件锁；重复启动复用现有服务和地址，不启动第二份后台服务；异常退出遗留的发现文件不阻止重开。激活接口校验随机实例令牌，客户端只连接回环地址。
- **关闭/刷新**：每个窗口建立独立持续连接，服务端检测连接断开；关闭最后一个窗口后约 10 秒退出，刷新有宽限期，另一个窗口还在则保持运行。连接由服务端每 15 秒维持活跃，不依赖浏览器关窗通知或后台 JS 计时器；异常失联还设有过期回收，系统睡眠唤醒有恢复时间。设置仍可立即退出。
- **多窗口存档**：保留版本冲突保护；冲突时读取最新存档，明确当前操作尚未保存。表单草稿（包括设置选项）保留，可直接重试；不会静默覆盖其他窗口的记录，也不会永久锁住全部保存操作。

### 14.2.1 共同瓶颈：本机尚未持有可复用登录会话

上表中 **C28（实时空位 / 预约）、C2（成绩在线读取）、C27（图书馆业务）不是各自独立的活**，
它们卡在同一个地基上：

- 当前只有**用户在浏览器里登录后的页面**能看到数据。官方页面登录成功
  **不等于**本机应用取得了可复用的会话或接口权限（见 14.1）。
- 本机既没有会话，也没有那些接口的**真实请求样本**（返回结构、字段、分页、权限差异
  都是未知）。此时写解析器只能靠猜，猜出来的东西会**报“成功/空位”但不真实** ——
  直接违反本项目的发布红线。
- 因此这三项在会话桥打通前不做，也不在发布说明里暗示已接通。

下一步若要推进，按这个顺序，且每一步都要有真实样本：

1. **会话桥最小验证**：用户自己登录后把会话交给本机（只存本机加密，不进源码、不进发布包），
   验证能用它重复取到同一份页面。账号密码与验证码始终不落地。
2. **抓一个真实只读请求**：确认时段数据到底是 HTML 渲染还是 JSON，弄清字段与分页。
3. **先只做查询**：写解析器并验证会话过期、无权限、无空位、断网四种情形都报错而不误报成功。
4. **预约提交最后做**，且属于写操作：必须由用户确认场地与时间后提交，失败不能报成功。
   在项目「不代替用户提交」的原则下，这一项始终要人亲自点确认。

## 19. 出口已被占用时的提示修复（2026-09-20）

起因：用户在教学区网络上点登录，看到「这个网络出口已经有账号在线了，本次登录没有生效」，据此认为登录失败、上不了网。

### 19.1 实测结论：那次登录其实生效了

直接向深澜门户的 `rad_user_info` 发只读查询（绕开本项目的客户端，避免被自己的解析逻辑误导），拿到的事实：

- `error: "ok"` —— 这个出口当时已处于已认证状态。
- 会话 `add_time` 就在用户操作的那一分钟内，`keepalive_time` 与查询时刻只差几秒 —— 会话是活的。
- `online_device_total: "1"`，`online_device_detail` 里那台设备上报的 `os_name` 是 `Mac OS`。
- 而 `Mac OS` / `Macintosh` 正是本项目登录请求里上报的参数（见 `srun.go` 的 `os` / `name`），所以那个在线会话就是本次登录建立的。

也就是说：**用户全程在线、能上外网**，只是被工具的提示误导了。

### 19.2 三个真实缺陷

1. **把"没生效"报成了成功**。`error: "ok"` + `suc_msg: "ip_already_online_error"` 被当成认证成功返回（`OK: true`），却又配了一句「本次登录没有生效」——同一句话里既说成功又说没生效。
   关键在于深澜的 **IP 级短路**：这个出口已有会话时，服务端在校验账号密码和 `ac_id` **之前**就返回了。它既没验证过这组凭据，也没验证过这个接入点编号。

2. **把没验证过的 `ac_id` 写进了缓存**。既然服务端是在校验 `ac_id` 之前短路的，这个编号就没有被证实过；缓存它会让用户下次在别的网络里拿着错值去认证，反而更难查。

3. **能上外网时反而跳过在线查询**。命令行与桌面界面各写了一份相同判断，理由是"不需要认证"。但用户问的是"我到底登上了没"，而"能上网"恰恰是已登录的最强证据。跳过查询的结果是一句干巴巴的"没查到"，用户以为掉线，跑去反复点登录，然后被 `ip_already_online` 挡回来——正好掉进最让人困惑的那个状态。
   附带问题：两处都把查询错误用 `_` 吞掉了，用户连为什么"没查到"都看不到。

### 19.3 修复

- `Login()`：`ip_already_online` 不再返回成功；提示改为能直接回答"我现在能不能上网"，并顺手查一次在线信息，把设备数、在线 IP 与设备描述带出来。
- `ac_id` 缓存：只在认证真正被服务端接受之后写入。
- 新增 `portal.QueryOnline()`，把"按区域查在线状态"收成**一处**，命令行与桌面界面共用（原先的重复实现已删除）。联网时两套协议都问一次——`Detect()` 联网时会提前返回、没跑协议指纹，无从得知当初是哪套协议认证的——谁在线采信谁。
- `OnlineStatus` 增加在线设备数与设备描述；`status` 命令与 `/api/status` 在联网时也给出结论，查询失败时显示失败原因，不再笼统地说"没查到"。

### 19.4 验证

- **真实网络复现**：同一台机器、同一时刻，仅二进制不同 —— 修复前 `账号状态: 没查到`；修复后 `账号状态: 已在线` + 在线 IP + `在线设备: Mac OS · ...`。
- 新增测试 8 项：出口被占用不报成功且不写缓存；账号自身在线仍算成功且正常缓存；在线设备字段解析（含「JSON 字符串里再套一层 JSON」的真实格式）；补充字段读坏不影响在线判断；`error` 字段是唯一在线判据（实测返回里没有 `user_name`）；联网时必须查询；深澜无结果时回落到宿舍区协议；校外不发起查询。
- `go test ./...` 全部通过，`go vet` 通过，Windows 构建成品冒烟全部通过。

### 19.5 遇到这条提示时该怎么办

先看工具给出的在线状态：

- **显示"已在线"且外网连通** —— 会话有效，不需要再登录。
- **想换成另一个账号** —— 必须先让出口上原有的会话下线；同一个出口 IP 只能挂一个账号。
- **"出口被占用"同时外网也不通** —— 这才是真需要处理的：原来那个会话很可能已失效但没有释放。

不要在"已在线"的状态下反复点登录：每次都会走一遍 `ac_id` 探测，而且这次登录同样不会生效。

### 21.1 官方校历依据及自动更新边界

### 21.2 预约和课表的后续实现顺序

1. 用户在学校官方页完成二次验证后，先核验静音舱的场地、用途、时段、本人预约记录，仅做读取。学校会话与校园网凭据分开处理，现有 ehall 成绩 Cookie 不发送到其他域名。
2. 依据实际认证机制决定接入方式：独立业务接口配合本机安全会话存储，或使用原生 WebView2 承载学校登录。当前 Edge / Chrome 应用窗口并非原生嵌入式浏览器，不能直接假定 iframe 能保留登录。不会移除学校的 iframe / CSP 防护来强行嵌入。
3. 时段查询和本人记录验收后，再做用户选定场地、日期、时段并确认提交的预约操作；不做自动抢位。本轮没有提交任何预约。
4. 本科入口来自[教务部](https://jwb.szu.edu.cn/)的课程表查询链接；研究生入口使用[学校学生页面](https://www.szu.edu.cn/jsrk/xs.htm)给出的研究生选课系统。当前应用只是提供官方查询入口，不声称已有本地课表。

### 25.1 实际协议与数据边界

- 本科事实参考：[LoveSzu TimetableApi.java](https://github.com/teleostnacl/LoveSzu/blob/main/Timetable/src/main/java/com/teleostnacl/szu/timetable/retrofit/TimetableApi.java)。个人课表为 `/jwapp/sys/wdkb/modules/xskcb/xskcb.do`，学期参数 `XNXQDM`；当前学期查询为 `jshkcb/dqxnxq.do`。本项目独立实现，没有复制参考项目代码，已加入中英 README 致谢。该参考实现较旧，当前账号实测仍是必要验收条件。
- 本科保留 `KCM / KCH / KXH / SKJS / YPSJDD` 课程、代码、课序、教师及时间地点原文；不猜测拆分周次和节次，不混用研究生规则。登录页、权限错误、无法识别的课程、条数不完整都不会变成空课表。缺少当前学期时允许用户填写校方学期。
- 社区接口依据是学校当前公开页面脚本。本轮实际读取 `/venue-api/booth/list`、`booth/info/{id}`、`boothType/info/{id}`、`booth/{id}/available-time`，与官方脚本的 48 格半小时和开放时段位图核对：1 为空闲，0 为已预约，-1 为不可选，未知值显示未确认。缺日期或不足 48 格明确报错。
- 公开查询走学校校内 HTTP 服务，不携带任何 Cookie 或账号；学校该主机 HTTPS 本轮不可用。带登录状态的请求固定走 `https://swzx.webvpn.szu.edu.cn/venue-api`，不跟随重定向，不降级到 HTTP。匿名请求本人记录实际返回 401，WebVPN 则转到认证页面。
- 预约 Cookie 先通过本人记录接口验证再标记连接；只在内存保管，不写庭院存档、日志或发布包。界面不展示校园卡号、开锁密码、手机号。本人记录支持 30 条分页，读取失败不显示为「没有预约」。
- 预约日期使用深圳时区，以学校返回的开放天数与上限检查。已开始的时段在本应用内不允许选择，界面明确说明；提交时再次通过 HTTPS 核验空位，最终业务权限和每日累计上限由学校裁定。不含抢位、自动循环提交、开锁或管理接口。

### 30.2 背景呈现

- **量化**：`campus.png` 从 1672×941 / **2.68MB** 压到 **694KB**（128 色 PNG-8，-74%）。像素画在放大对比图上看不出差别，q64 才会让湖面反光发平，故选 128 色。嵌入资源总量 3840KB → 1785KB，Windows 成品 11.6MB → **9.6MB**。
- **压暗**：`body::before` 从 4% 平铺薄纱改为竖向渐变（顶部 8%，250px 处 13%，460px 后 40–45%）。顶部保留清晰的文山湖场景给木牌，进入内容区后背景退到纸面卡片后面。原因：原先整屏高饱和细节与卡片抢注意力，纸面与背景之间是硬边。
- 未改动美术本身；`看看像素校园` 大图浏览读的是原图，不受压暗影响。若之后仍觉得画面不好看，再按「黄昏暖调、低饱和、中间留白、去掉游戏梗物件」重新生成。
