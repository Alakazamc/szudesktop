# 深大校园网连不上？先别急，病根大概率在这篇里

> 写给深圳大学的同学们，尤其是刚搬进宿舍、插上网线却上不了网的新生。
> 本文是第三方整理，不是官方文档；学校随时可能调整认证方式，以信息中心页面为准。
> 最后更新：2026-09-15

---

## 先讲一个场景

周日晚上十一点，论文明天要交，网页一直在转圈。你重启了电脑，忘了 WiFi 再连回来，还是转圈。

这时候大多数人的第一反应是搜教程。搜出来的教程眼花缭乱：有人让你装 Dr.COM 客户端，有人让你打开某个神秘网址，还有人贴了一段 2023 年的脚本——**照着做，一百遍也没用。**

不是你的问题，是教程过期了。

## 为什么老教程集体失效：2025 年寒假的大手术

深大的校园网认证在 **2025 年寒假**动过一次大改造，从此分成两套并存的系统：

- **教学区、办公区、图书馆**：从老的 Dr.COM 换成了**深澜（SRun）**系统。登录从"填个表单点提交"变成了五道加密工序——取挑战值、HMAC-MD5 加密密码、XXTEA 加密用户信息、自定义字母表 Base64、SHA1 校验和。**2024 年及以前写的教学区脚本，全部作废。**
- **宿舍区（含教工区）**：还是 Dr.COM 的新版网页认证，一个 GET 请求就能登录，简单得多。

所以看任何教程、挑任何工具，**第一件事是确认它写的是 srun（教学区）还是 drcom / eportal（宿舍区）**。区域搞错，神仙难救。

## 第一步永远是：认清你站在哪张网

深大有四类上网场景，认证入口完全不同。**九成的"连不上"，是走错了入口。**

| 场景 | 连什么 | 认证入口 |
|---|---|---|
| 教学区、办公区、图书馆（无线） | `SZU_WLAN` | `net.szu.edu.cn` |
| 宿舍区（无线） | `SZU_CTC&CMCC` | `172.30.255.42` |
| 宿舍区（有线，插墙上网口） | 墙上网口 | `172.30.255.42` |
| 校外访问校内资源 | — | 零信任系统 / WebVPN |

**账号统一是 6 位数字的校园卡号**（不是学号！），密码是统一身份认证密码。没激活过的先去 `authserver.szu.edu.cn` 激活；老生的默认密码是身份证后 8 位。

一个高频卡点：**认证页面死活不弹出来。**别等它弹，直接打开浏览器手动输上面表格里的地址。iPhone 和 iPad 特别容易不弹，这是系统行为，不是网络坏了。

## 三连问：能砍掉大部分瞎折腾

连不上的时候，按顺序问自己三个问题：

**1. 我到底在哪张网？**
看 WiFi 名字，或者看插的是不是宿舍墙上的网口。走错入口是最常见的原因。

**2. 是不是根本没开通套餐？**
这是第二大原因。注意一个反直觉的点：**在宿舍区开通了套餐的同学，教学办公区可以免费用**（学校给 2 个并发名额），不用重复买。反过来，宿舍区没开过的，教学区也用不了。

**3. 是停机了，还是密码错了？**
去 `www1.szu.edu.cn/nc` 的自助服务看套餐到期时间。**系统每月 1 日自动检测，到期就断网，没有任何提醒。**

## 报错文案对照表（建议收藏这一节）

下面这些提示都是官方文档里记录过的原文。**对着提示找原因，比反复重连有用得多。**

### 宿舍区常见提示

| 你看到的提示 | 真实原因 | 怎么办 |
|---|---|---|
| 您尚未办理校内上网套餐，请登录自助服务系统办理 | 套餐扣费失败、没开通，或已到期 | 查校园卡「通用代扣费账户」余额，再回自助服务重新圈费 |
| 客户端认证失败：本时段禁止使用 | 账号停机或没订套餐 | 同上 |
| 账号不存在 | 账号输错了 | 是 6 位校园卡号，不是学号 |
| 统一身份认证密码错误 | 密码错了 | 清空重输；忘了就去重置 |
| 登陆失败[05] | 网卡驱动不稳定，或客户端装坏了 | 重装官方客户端；电信 26414134、移动 18476328678 |
| 登陆超时失败 | 网线没插好，或墙上端口坏了 | 换个端口试；坏了打 26414134 报修 |
| 系统网络未准备好，请检查网络连通性 | 网线、转接器或端口有问题 | 同上；USB 转网口建议买亚信芯片的 |
| 您没有设置网关地址 | 装过某些"免费 WiFi"类工具 | 卸载它们，重装官方客户端 |
| 重复登录 | 其实已经登录成功了，是代理或域名解析在捣乱 | 重置一遍网络设置 |
| 端口被占用 | 注册表里的网络组件值变成乱码 | 较麻烦的故障，优先考虑重装客户端 |

### 两个区都会犯的病

| 现象 | 真实原因 | 怎么办 |
|---|---|---|
| 登录成功，但只能上校内，外网打不开 | 系统或浏览器里开着代理 | 关掉代理（见下一节） |
| 网络连接显示「网络电缆被拔出」 | 墙上端口被封禁或损坏 | 换端口，或网上报修 |
| 弹出「网络上有重名」/ 主机名冲突 | 电脑名和别人的撞了 | 改一下计算机名 |
| 网络反复断开又自动连上 | 中了 ARP 病毒，或用过 P2P 终结者这类限速工具 | 校内设备会自动踢你下线 30 秒左右；杀毒 + 装 ARP 防火墙 |
| 宿舍 WiFi 一直转圈、提示无 IP、已停用 | 手机开了「随机 MAC 地址」 | 改成使用设备真实 MAC 地址 |
| iPhone 连上却显示无互联网 | 没弹认证页 | 手动开 Safari 输 `net.szu.edu.cn`（教学）或 `172.30.255.42`（宿舍） |

## 代理和加速器：最常见的隐形杀手

这点网上讲得少，但实际踩坑的人非常多。

Clash、Mihomo 这类代理工具会占用 `198.18.0.0/15` 这个"假 IP 段"来接管流量。**校园网认证请求一旦被它抓走，就会失败或者一直转圈。**认证阶段建议：

- 暂时关掉代理；
- 或者把认证服务器地址加进直连规则；
- 如果域名解析也被代理接管了，`net.szu.edu.cn` 可能根本解析不到——这时可以绕开域名，直接向服务器 IP 发请求并带上域名头。

## 一次说清那些流传很广的说法

**"宿舍宽带能不能几个人合买？"**
不能。**一个账号同时只能登录 1 台电脑 + 2 台移动终端**，所以基本人手一个账号。
（网上关于这个数字的说法很乱：有说 1 台手机的，有说宿舍 3 台的。以官方《学生宿舍区网络使用及收费说明》为准。）

**"宿舍买了套餐，去图书馆还要再买吗？"**
不用。宿舍套餐生效期间，教学办公区免费上网，给 2 个并发名额，带宽按校园网规定走。

**"为什么这么慢、还老掉线？"**
宿舍 WiFi 的设备装在走廊天花板上，信号穿墙进宿舍本来就有损耗，金属柜子挡着更明显。**插网线不受这些影响，是最有效的提速手段。**

**"套餐到期为什么一句提醒都没有就断了？"**
系统每月 1 日检测，到期自动断网，不另行通知。要在到期当月**提前预约下一次套餐**（移动用户要提前到月底前三日），时间才会自动顺延。另外每天 `22:30–03:00` 是系统结算时间，办不了任何宽带业务。

## 懒人方案：让机器替你登录

不想每次手动认证的话，社区有一批开源工具。挑之前看两点：

**第一，密码存在哪。**优先选把凭据交给系统安全设施的——macOS 钥匙串、Windows DPAPI、Linux Secret Service，而不是明文写进配置文件。

**第二，第三方工具和官方客户端互斥。**学校明确说过同时使用会互相踢下线。别一边开着官方客户端一边跑自动脚本。

我自己写了一个，在持续维护：

- **szuDesktop / szunet**：同一个项目的两个入口——`szunet` 是命令行，Windows / macOS / Linux 三端各一个单文件、无运行时依赖；`szuDesktop` 是本文配的那个像素风图形客户端，**目前只发 Windows 版**，校园网状态、登录、断线诊断、公告与校历都在里面。两者共用同一套认证逻辑：自动判断你在教学区还是宿舍区，走对应的协议；`szunet diag` 把「哪个区、门户通不通、解析正不正常」一次列出来——相当于把这篇文章自动化了一遍。密码存放：Windows DPAPI 加密、macOS 钥匙串、Linux Secret Service，**三端都没有明文兜底**——机器上没有对应的系统安全设施时会明确报错，不会偷偷写一个明文文件（项目 STATUS.md 的 F24）。
