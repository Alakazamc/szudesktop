# 深圳大学校园网：连不上时，先看这张表

> 面向深大在校学生，尤其是刚入学、插上网线却上不了网的新生。
> 本文是第三方整理，不是官方文档。学校随时可能调整认证方式，以信息中心页面为准。
> 最后更新：2026-09-14

---

## 为什么你搜到的教程不管用

深大的校园网在 **2025 年寒假**动过一次大手术。

- **教学区、办公区、图书馆**：从老的 Dr.COM 换成了**深澜（SRun）**。登录流程从"填个表单点提交"变成了要算五道加密——取挑战值、HMAC-MD5 加密密码、XXTEA 加密用户信息、自定义字母表 Base64、SHA1 校验和。结果就是：**2024 年及以前写的教学区自动登录脚本，集体失效。**
- **宿舍区（含教工区）**：仍然走 Dr.COM 的新版网页认证，一个 GET 请求就能登录，简单得多。

所以你网上搜到的教程，第一步永远是先确认它写的是 **srun（教学区）** 还是 **drcom / eportal（宿舍区）**。写错区域的教程，照着做一百遍也没用。

---

## 第一步：先确认你在哪张网

深大有四类上网场景，认证入口完全不同。**九成的"连不上"，是走错了入口。**

| 场景 | 连什么 | 认证入口 |
|---|---|---|
| 教学区、办公区、图书馆（无线） | `SZU_WLAN` | `net.szu.edu.cn` |
| 宿舍区（无线） | `SZU_CTC&CMCC` | `172.30.255.42` |
| 宿舍区（有线，插墙上网口） | 墙上网口 | `172.30.255.42` |
| 校外访问校内资源 | — | 零信任系统 / WebVPN |

**账号统一是 6 位数校园卡号，密码是统一身份认证密码**（没激活过的先去 `authserver.szu.edu.cn` 激活；老生默认是身份证后 8 位）。

一个常见卡点：认证页面不弹出来。**不要等它弹**，直接打开浏览器手输上面表格里的入口地址。iPhone 和 iPad 特别容易不弹，这是系统行为，不是网络坏了。

## 第二步：三步自检

连不上时按顺序问自己三个问题，能砍掉大部分瞎折腾：

**1. 我到底在哪张网？**
看 WiFi 名字，或者看插的是不是宿舍墙上的网口。走错入口是最常见的原因。

**2. 是不是根本没开通套餐？**
这是第二大原因。在宿舍区开通了套餐的同学，**教学办公区是可以免费用的**（学校给两个并发名额），不用重复买。反过来，没在宿舍区开过的，教学区也用不了。

**3. 账号是停机状态还是密码错了？**
去 `www1.szu.edu.cn/nc` 的自助服务里看套餐到期时间。**系统每月 1 日自动检测，到期就断网**——不会提醒你。而且停机后重新开通，**只能恢复原来的运营商和原套餐**，想换得等到下次订购时预约。

## 第三步：报错文案对照表（本文核心）

下面这些提示，是官方文档里记录过的原文。**对着提示找原因，比反复重连有用。**

### 宿舍区常见提示

| 你看到的提示 | 真实原因 | 怎么办 |
|---|---|---|
| 您尚未办理校内上网套餐，请登录自助服务系统办理 | 套餐扣费失败、没开通，或已到期 | 查校园卡「通用代扣费账户」余额，再回自助服务重新圈费 |
| 客户端认证失败：本时段禁止使用 | 账号停机或没订套餐 | 同上 |
| 账号不存在 | 账号输错了 | 必须是 6 位数的校园卡号，不是学号 |
| 统一身份认证密码错误 | 密码错了 | 清空输入框重新输；忘了就重置 |
| 登陆失败[05] | 网卡驱动不稳定，或客户端装坏了 | 重装官方客户端；电信 26414134、移动 18476328678 |
| 登陆超时失败 | 网线没插好，或者墙上端口坏了 | 换个端口试，坏了就打 26414134 报修 |
| 系统网络未准备好，请检查网络连通性 | 网线、转接器或端口有问题 | 同上。USB 转网口建议买亚信芯片的 |
| 您没有设置网关地址 | 装过某些"免费 WiFi"类工具 | 卸载它们，重装官方客户端 |
| 重复登录 | 其实已经登录成功了，是代理或域名解析出了问题 | 重置一遍网络设置 |
| 端口被占用 | 注册表里的网络组件值变成乱码了 | 属于较麻烦的故障，优先考虑重装客户端 |

### 教学区常见提示

| 你看到的提示 | 真实原因 | 怎么办 |
|---|---|---|
| ldap auth error | 密码错；另外密码不要超过 16 位 | 改一次统一身份认证密码再登 |
| Rad:userid error1 | 账号错 | 核对 6 位校园卡号 |
| 账号或密码错误 | 账号或密码错 | 逐项核对 |

### 跨区域的通病

| 现象 | 真实原因 | 怎么办 |
|---|---|---|
| 登录成功，但只能上校内，外网打不开 | 系统或浏览器里开着代理 | 关掉代理设置 |
| 网络连接显示「网络电缆被拔出」 | 墙上端口被封禁或已损坏 | 换端口，或直接网上报修 |
| 弹出「网络上有重名」/ 主机名冲突 | 电脑名和同一网络里别人的撞了 | 改一下计算机名 |
| 网络反复断开又自动连上 | 中了 ARP 病毒，或用过 P2P 终结者这类限速工具 | 校内设备会自动踢你下线 30 秒左右。杀毒 + 装 ARP 防火墙 |
| 宿舍 WiFi 一直转圈、提示无 IP、已停用 | 手机开了「随机 MAC 地址」 | 改成使用设备真实 MAC 地址 |
| iPhone 连上却显示无互联网 | 没弹认证页 | 手动开 Safari 输 `net.szu.edu.cn`（教学）或 `172.30.255.42`（宿舍） |

## 第四步：如果你在用代理或加速器

这一点网上讲得少，但实际很常见。

开着 Clash、Mihomo 这类代理工具时，它们会占用 `198.18.0.0/15` 这个"假 IP 段"来做流量接管。**校园网认证请求一旦被它抓走，就会失败或者一直转圈。** 认证阶段建议：

- 暂时关掉代理；
- 或者把认证服务器的地址加进直连规则；
- 如果域名解析也被代理接管了，`net.szu.edu.cn` 可能根本解析不到。这种情况下可以绕开域名解析，直接把请求发到服务器 IP 并带上域名头。

## 几个流传很广的误解

**"宿舍宽带能不能几个人合买？"**
不能。**一个账号只能同时登录 1 台电脑 + 2 台移动终端**。这也是为什么基本都是人手一个账号。
（注：网上关于这个数字的说法很乱，有的写 1 台手机，有的写宿舍 3 台、教学区 1 台。以官方《学生宿舍区网络使用及收费说明》为准。）

**"宿舍买了，去图书馆还要再买吗？"**
不用。宿舍区套餐生效期间，教学办公区可以免费上网，学校给 2 个并发名额，带宽按校园网规定走，和你买的宿舍套餐速度无关。

**"为什么这么慢、还老掉线？"**
宿舍 WiFi 的设备装在走廊天花板上，信号穿墙进宿舍本来就有损耗，金属柜子挡着更明显，周围 WiFi 少也会有干扰。**插网线不受这些影响**，这是最有效的提升手段。

**"套餐到期为什么没提醒就断了？"**
系统每月 1 日检测，到期自动断网，不另行通知。**要在到期当月提前预约下一次套餐**（移动用户需要提前到月底前三日），时间才会自动顺延。另外每天 `22:30–03:00` 是系统结算时间，办不了任何宽带业务。

## 想省事：自动登录工具怎么选

如果你不想每次手动认证，社区有一批开源工具。选之前注意两点：

**第一，看密码存在哪。** 优先选把凭据交给系统安全设施的——macOS 交给钥匙串、Windows 交给 DPAPI，而不是把密码明文写进配置文件。这是安全性上最实在的区别。

**第二，第三方工具和官方客户端是互斥的。** 学校明确说明过，同时使用会互相踢下线。**别一边开着官方客户端，一边跑自动脚本。**

另外要清楚：这些都是社区第三方作品，与学校无关，学校也不会为它们的问题负责。

## 配套工具：szuNet

上面这些排查步骤，我写成了一个命令行小工具，省得每次手工比对。

**szuNet** 支持 Windows / macOS / Linux 三端，编译出来是**单个文件，不含任何运行时依赖**，
下载下来直接跑，不用装 Python、不用装 Node。它做两件事：

1. **自动登录**：自动判断你在教学区还是宿舍区，走对应的那套协议
2. **诊断**：`szunet diag` 会把「你在哪个区、两个认证门户通不通、域名解析正不正常、
   账号在不在线」一次性列出来，并给出对应的排查结论——也就是这篇文章的自动化版本

密码不会明文落到磁盘：macOS 存钥匙串、Windows 走 DPAPI 加密、
Linux 走 Secret Service（没有则退化成权限 600 的文件）。
